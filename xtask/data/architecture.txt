# Architecture rules, checked by `cargo xtask check` (docs/development.md).

# Crate dependencies, any kind (normal, build, dev): crate <package> -> <allowed packages...>
# A package without a line fails, so a new crate or dependency is a decision written here.

# gpu is C (gpu/oos-gpu.c): no crate, no rule.

# Module rules over a crate's top-level modules (the first name after crate::):
#   forbid <crate dir> <from> <to>          code under src/<from>.rs or src/<from>/ must not name crate::<to>
#   layer <crate dir> <module> -> <mods...> code of <module> may name only these modules and itself
# The target layers of ui are in docs/architecture/README.md (Enforcement); migration steps add them as the tree meets them.
#
# Metrics allowlist: statics with interior mutability (locks, atomics, cells, once/lazy values) that may stay.
#   static <file> <name>     <name> as the gate prints it: NAME, or <function>::NAME inside a function
# Every other mutable static is global state: the old ones are in statics.txt (shrink only), new ones fail.

# Confinements: confine <crate dir> <path> -> <modules...>
# <path> (a crate module path, or a dependency path such as oos_hal::dho) may be named only from inside the listed
# modules, and a crate path also from inside itself. Test code is free.
# The board boundary (docs/porting.md): only board::dho uses the DHO hardware layer, and nothing outside board names
# board::dho (board/mod.rs selects the port: `Active`). The same boundary as the board::boundary test it replaces.
